# 3. 정보를 깔끔하게 정리하는 디지털 서랍장 만들기 (데이터베이스와 백엔드, 40시간, 필수) — 마감 10/10

## 1. 미션 소개
엑셀과 DB의 차이는 '데이터가 얼마나 많냐'가 아닙니다. 테이블 사이의 '관계'를 표현할 수 있냐의 차이입니다. 그 관계를 모르면 JOIN도 ORM도 계속 헷갈립니다. 여기서 제대로 잡아두면 뒤가 편합니다. 테이블 설계부터 시작해서, 요구사항을 SQL 쿼리 하나로 해결하는 흐름을 직접 완성합니다.

이 미션에서는 백엔드 프레임워크 없이, 도메인에 맞는 테이블 구조를 설계하고(PK/FK/제약조건) 직접 데이터를 넣고(INSERT) 필요한 정보를 뽑는(SELECT/JOIN/GROUP BY) 전체 흐름을 실습합니다. 이후 JPA/ORM을 학습할 때 필요한 관계(1:N), 키(PK/FK), 무결성, 조인 기반 조회 사고방식을 먼저 체득하게 됩니다.

## 2. 최종 결과물 (백엔드 프레임워크 사용 금지)
- **도메인 데이터베이스 1개 설계**: 자유 주제(도서 대여, 영화 평점, 카페 주문, 여행 일정, 학급 관리 등)로 최소 4개 테이블, 1:N 관계 최소 2개 이상
- **스키마 생성 스크립트 1개**: CREATE TABLE로 PK/FK/제약조건 포함, 실행 순서대로 정리된 .sql 파일 1개
- **샘플 데이터 입력 스크립트 1개**: 각 테이블당 최소 10행 이상
- **핵심 쿼리 15개 + 실행 결과 캡처**: 조회/조인/집계/서브쿼리/수정 및 삭제 포함, 각 쿼리 실행 결과 스크린샷(또는 결과 텍스트)

## 3. 과제 목표
- 데이터베이스가 "엑셀과 뭐가 다른지", 왜 테이블로 나눠 저장하는지 설명할 수 있다.
- PK/FK가 무엇이고, 1:N 관계가 데이터를 어떻게 연결하는지 설명할 수 있다.
- SELECT / INSERT / UPDATE / DELETE를 언제 쓰는지 구분할 수 있다.
- JOIN과 GROUP BY로 연결된 데이터를 한 번에 뽑는 방법을 설명할 수 있다.
- 검색/정렬/집계/랭킹을 SQL로 어떻게 풀지 감을 잡을 수 있다.
- 인덱스가 왜 필요한지, 어떤 컬럼에 적용하면 좋은지 기초적인 이해를 할 수 있다.

## 4. 기능 요구 사항
### DB 환경 준비
- 로컬에서 실행 가능한 DB 설치 (SQLite, MySQL, PostgreSQL, H2 중 택1)
- SQL 실행 도구 준비 (DBeaver, TablePlus, DataGrip, CLI 등)
- SQLite: 설치 가장 간단, 파일 기반(입문자 추천) / MySQL: 실무에서 가장 널리 사용 / PostgreSQL: 표준 SQL 준수율 높음 / H2: Java 환경, 인메모리 모드
- 가급적 표준 SQL 범위 내 작성 권장, DB 고유 문법 사용 시 주석으로 명시

### 데이터 모델(스키마) 설계
- 최소 4개 테이블, 각 테이블은 PK를 가짐
- 최소 2개 이상의 FK로 1:N 관계
- 컬럼 타입을 의미에 맞게 선택 (TEXT/VARCHAR, INTEGER, DATE/DATETIME 등)
- 테이블/컬럼 이름은 역할이 드러나도록 (member, rental, created_at 등)
- 주제 예시: 도서 대여(회원, 도서, 대여 기록, 카테고리) / 영화 평점(사용자, 영화, 리뷰, 장르) / 카페 주문(고객, 메뉴, 주문, 주문 상세) / 온라인 쇼핑(회원, 상품, 주문, 주문 상세) / 학급 관리(학생, 과목, 성적, 교사)

### 제약조건 적용
- 최소 1개 컬럼에 NOT NULL, 최소 1개 컬럼에 UNIQUE
- FK가 실제로 동작하도록 설정 (없는 값 참조가 막혀야 함)

### 샘플 데이터 준비
- 각 테이블 최소 10행 이상, FK로 연결된 데이터가 실제 관계를 갖도록
- FK가 참조하는 부모 테이블에 데이터가 먼저 존재해야 함

### 핵심 SQL 쿼리 15개 작성
- 기본 조회 4개 이상 (WHERE, ORDER BY, LIMIT 포함)
- 조인 4개 이상 (INNER JOIN 2개 이상, LEFT JOIN 1개 이상)
- 집계 3개 이상 (COUNT, SUM, AVG 중 2개 이상 + GROUP BY)
- 서브쿼리 1개 이상
- 데이터 수정 및 삭제 2개 이상 (UPDATE, DELETE)
- 인덱스 1개 이상 (CREATE INDEX + 적용 이유 1줄)

### 결과 확인 자료
- 쿼리마다 실행 결과 확인, 각 쿼리에 "무엇을 확인하는 쿼리인지" 한 줄 설명
- 스크린샷 또는 결과 텍스트

### 제출물 구성
- 스키마 생성 SQL 1개
- 샘플 데이터 INSERT SQL 1개
- 쿼리 15개 SQL 1개
- 실행 결과 캡처 폴더 1개
- (선택) ERD 다이어그램 이미지 1개 (draw.io, dbdiagram.io 등)

## 5. 보너스 과제
- 조인 1개를 두 방식으로 풀기: 같은 요구를 JOIN과 서브쿼리로 풀고 비교
- 데이터 정합성 깨뜨려 보기: 일부러 FK 에러 입력을 시도하고 왜 막히는지 기록
- 미니 리포트 만들기: "이 DB로 뽑을 수 있는 핵심 지표 3개" 정의 및 SQL 정리 (월별 대여 건수 추이, 인기 도서 TOP 10, 연체율 높은 회원 등)

## 7. 제약 사항
- 백엔드 프레임워크 사용 금지 (Spring/Django/Express 등)
- 로컬에서 실행 가능한 DB만 사용
- 뷰(View), 프로시저, 트리거 같은 고급 기능 사용 안 함
- 정규화 이론을 과도하게 깊게 파지 않음

## 8. 결과 예시
- 주제 "도서 대여": 테이블 member, book, rental, category
- 관계: rental.member_id → member.id, rental.book_id → book.id
- 쿼리 예시: 대여 중인 책 목록, 회원별 대여 횟수 집계, 최근 30일 대여 기록, 연체 상태로 업데이트, 대여 기록이 없는 회원 찾기(서브쿼리)
